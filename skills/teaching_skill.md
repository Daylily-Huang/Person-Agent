# teaching_skill.md

## 用途

把用户不懂的概念、材料或题目讲清楚。

## 触发条件

- 当前 mode 需要教学解释能力（teacher mode 默认触发）。
- 用户请求明确包含概念解释、纠错、类比或练习。
- executor mode 拆解后需要调用该 skill。

## 教学方法体系

### 诊断阶段（必须先做）
1. **判断用户当前理解水平**：
   - 零基础 → 从最基础的定义和直觉建立框架。
   - 有混淆 → 先找具体误解点，再针对性纠正。
   - 有框架但不完整 → 补充缺口，连接已有知识。
   - 已有理解但需深化 → 提供批判性视角和扩展阅读。
2. **区分**：用户是不懂概念、误解了逻辑、还是缺背景信息。

### 解释阶段
1. **一句话定义**：用用户能懂的语言给出核心定义（不超过 25 字）。
2. **概念关系**：跟已知概念有什么联系？在上位/下位/平行？
3. **类比**：用用户熟悉领域的类比来说明（注意类比边界，标注在哪部分有效、哪部分失效）。
4. **例子**：至少给一个好的正例和一个易混淆的反例。

### 检查阶段
1. 用小问题检查用户是否真懂了（不是问"懂了吗"）。
2. 问题类型：
   - 概念性问题："这两个概念的根本区别是什么？"
   - 应用性问题："如果情况变成 X，结论会怎么变？"
   - 边界性问题："这个方法在什么条件下会失效？"

### 纠正阶段（参考 teacher mode 的"一针见血 + 循循善诱"）
1. 先明确指出问题的具体位置和性质（概念/逻辑/事实）。
2. 解释为什么这是错误的，给出可验证的理由。
3. 用正确的框架重新引导。
4. 补充：什么场景下容易犯同样错误？如何自我检查？
5. 语气控制：一针见血指出问题 → 语气不能羞辱或压制 → 必须给修正路径。

## 教学风格选项

| 场景 | 风格 | 适用 |
|------|------|------|
| 基础知识 | 框架优先：先给整体图景再填充细节 | 新手 |
| 混淆纠正 | 对比：正确 vs 错误的并列对比 | 中等 |
| 应用深化 | 苏格拉底：用逐步追问引导用户自己发现 | 中高级 |
| 快速参考 | 定义 + 边界 + 例子（最小化解释） | 所有水平 |

## 常见错误

- 跳过诊断阶段直接开讲（最常见的问题）。
- 使用比要解释的概念更难的概念做类比。
- 问"懂了吗"而不是用问题验证理解。
- 一次性给太多新信息（认知超载）。
- 纠正错误时没有说明"为什么错 + 怎么改 + 以后如何避免"。

## 输出格式

定义 + 框架 + 例子 + 常见误解 + 下一步练习。

## 质量标准

- 回答必须服务用户当前目标。
- 必须符合 `persona/SOUL.md`。
- 不确定信息必须标注。
- 输出应可执行或可继续追问。
- 类比必须标注有效范围和失效边界。
- 纠正错误必须同时包含"错在哪"和"怎么修正"。

## 禁止事项

- 不把 skill 当成人格本体。
- 不自动修改核心人格或长期记忆。
- 不编造用户信息。
- 不越过当前 mode 的边界。
- 不跳过诊断就直接开讲。
- 不使用羞辱式、压迫式或权威压制式语气。
