# planning_skill.md

## 用途

把复杂任务拆成可执行步骤并建立检查点。

## 触发条件

- 当前 mode 需要任务规划能力（executor mode 默认触发）。
- 用户请求明确包含多步骤任务或不确定如何开始。
- 另一 skill 识别到任务复杂需要先拆解。

## 执行流程 — 详细版

### 阶段 1：定义与对齐
1. **澄清目标**：用户真正想完成的是什么？区分"想要做"和"需要实现的结果"。
2. **约束收集**：时间、资源、技能、工具、权限、依赖项。
3. **完成标准**：什么状态算"做完"？可验证的客观标准是什么？
4. **风险预估**：哪些环节最容易出问题？备选方案是什么？

### 阶段 2：拆解与排序
1. **MECE 分解**：将大目标拆成互斥且穷举的子任务。
2. **依赖关系图**：哪些任务必须先做？哪些可以并行？
3. **优先级排序**：关键路径上的任务优先；高风险环节优先验证。
4. **时间估计**：每步的乐观/悲观/最可能耗时。

### 阶段 3：执行框架
1. 为每一步定义：**做什么 → 怎么做 → 怎么验证做完**。
2. 关键决策点设置检查站（Go/No-Go check）。
3. 信息不充分的任务标记为"调研后定"。

### 阶段 4：验证与复盘
1. 所有完成标准逐项检查。
2. 复盘：实际 vs 计划差异在哪？学到了什么？
3. 产出物归档（结果、决定、遗留问题）。

## 任务复杂度分级

| 级别 | 特征 | 方法 |
|------|------|------|
| 简单 | 单步骤，已知路径 | 直接执行，不需要正式 plan |
| 中等 | 3-8 步，确定性高 | 步骤清单 + 检查点 |
| 复杂 | >8 步或有未知因素 | 完整 4 阶段流程 |
| 混沌 | 目标模糊或路径完全未知 | 先调研缩小范围，再降级为复杂 |

## 常见错误

- 跳过"定义完成标准"就直接开做。
- 低估未知因素的占比（规划谬误）。
- 把"计划"本身当成产出，忽略了验证。
- 没有预留缓冲时间。
- 没有识别关键路径上的单点故障。

## 与复盘的关系

计划执行完成后，自动建议复盘或检查。复盘内容通道：
- 成功部分：可以沉淀为 `memory/project_memory.md` 的约定。
- 失败/延误部分：分析原因 → 输出为下一次计划的检查项。

## 输出格式

目标 + 阶段 + 行动清单 + 验证标准。

## 质量标准

- 回答必须服务用户当前目标。
- 必须符合 `persona/SOUL.md`。
- 不确定信息必须标注。
- 输出应可执行或可继续追问。
- 任务拆解应覆盖主目标，不过度拆解到冗余细节。
- 完成标准必须可验证（可观测事件或可度量结果）。

## 禁止事项

- 不把 skill 当成人格本体。
- 不自动修改核心人格或长期记忆。
- 不编造用户信息。
- 不越过当前 mode 的边界。
- 不为显示全面而过度拆解简单任务。
