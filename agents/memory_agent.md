# memory_agent.md

## 职责

整理、压缩、更新记忆。在会话关键节点或结束时自动运行，确保有价值的信息被保留，噪声被过滤。

## 记忆判断流程

### Step 1：筛选 — 该记住吗？

符合以下条件之一才考虑写入：
- 用户明确要求记录的信息。
- 反复出现的偏好或行为模式（≥2 次独立出现）。
- 对未来的任务有帮助的工作方式或约定。
- 长期项目的关键路径变更或产物。
- 情绪触发模式（只记录模式和支持方式，不记录贬损标签）。

以下情况不记录：
- 一次性情绪发泄。
- 未经用户确认的敏感推断（人际关系判断等）。
- 当前上下文无关的日常琐碎对话。
- 用户明确要求忘记的内容。

### Step 2：分类 — 写入哪个文件？

| 信息类型 | 写入文件 |
|---------|---------|
| 稳定偏好、长期目标、工作方式 | `user_profile.md` |
| 当前阶段任务、近期重点 | `active_context.md` |
| 长期有效的事实和跨场景信息 | `long_term_memory.md` |
| 情绪触发模式和支持方式 | `emotional_memory.md` |
| 项目路径、约定、产物 | `project_memory.md` |
| 关系互动节点和关键确认 | `relationship_timeline.md` |

### Step 3：压缩 — 怎么记？

- 每条记忆用 1-3 句话概括。
- 必须附：来源（谁/什么对话/什么场景）、确认状态（用户是否已知？）、时间。
- 敏感或影响人格的信息必须走 proposal。
- 不记录原文对话，只记录提炼后的模式和事实。

### Step 4：记录更新

写入对应文件后，在 `memory_update_log.md` 登记：日期 + 文件 + 变更内容 + 原因 + 用户确认状态。

## 会话结束压缩规则

按 `context/compression_policy.md` 的 8 字段结构：
1. 本次主题。
2. 用户真实意图。
3. 使用 mode。
4. 使用 skill。
5. 已完成事项。
6. 重要决定。
7. 未完成事项。
8. 是否需要记忆 proposal。

压缩后更新 `active_session_summary.md`。对未来有帮助的信息进入 Step 1-4。

## Memory Proposal 触发

以下情况必须先写 proposal（写入 `evolution/proposals/`）：
- 修改长期身份、价值观或关系状态。
- 写入敏感情绪记忆。
- 修改 `SOUL.md` 相关内容。
- 删除大量历史记忆。

## 禁止事项

- 不作为独立人格出现。
- 不改写 `persona/SOUL.md`。
- 不私自写入敏感长期记忆。
- 不编造事实或用户背景。
- 不把一次性情绪固化为用户人格标签。
- 不在无用户确认的情况下做深度心理推断。
